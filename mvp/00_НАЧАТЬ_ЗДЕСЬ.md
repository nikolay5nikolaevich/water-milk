# Комплект MVP «АкваМилк»

Материалы для демонстрации 3 ноября 2026 года. Воронку и Telegram настраивает исполнитель в amoCRM; база, оценка и сценарии подготовлены в этой папке.

**Весь комплект уже работает на учебных условиях.** Реальные сведения о компании не предоставлены. Цены, товар, доставка, расписание и диалоги ниже придуманы для теста и не описывают деятельность «АкваМилк». Условия нельзя отправлять реальным клиентам.

## Твоя часть: заполнить только этот блок

- Ссылка на тестовую воронку: **не заполнено**.
- Название подключённой Telegram-интеграции и тип канала (бот / другое): **не заполнено**.
- Тестовый Telegram для отправки сообщений: **не заполнено**.
- Ответственный за обращения: **не назначен**.
- Проверяющий качества и владелец учебной базы (можешь быть ты): **не назначен**.
- Где сотрудник открывает базу (ссылка или путь): **не заполнено**.
- Режим задач: **не проверен** — после настройки указать «автоматически» или «вручную: причина».
- Ссылка на тестовую сделку для показа: **не заполнено**.

## Что сделать в amoCRM

1. Создать тестовую воронку: «Новое обращение» → «В работе» → «Ожидание клиента» → два штатных финальных этапа.
2. Назначить себя ответственным; при необходимости добавить поле «Тип запроса». Не дублировать штатные поля.
3. Подключить тестовый Telegram. Проверить первое сообщение, ответ из CRM и повторное сообщение без лишней сделки.
4. Поставить два триггера: при входе нового обращения — задача ответить через 15 минут; на каждом финальном этапе — задача проверить качество через день. Если автоматизация недоступна, создать задачи вручную и записать это выше.
5. Разместить ссылку на [базу знаний](01_БАЗА_ЗНАНИЙ.md) в доступном сотруднику месте.
6. Воспроизвести диалог D02 из [тестовых диалогов](03_ТЕСТОВЫЕ_ДИАЛОГИ.md), зафиксировать исход в примечании, закрыть обращение и проверить задачу на оценку.
7. Отметить фактические результаты CRM в [журнале](05_ЖУРНАЛ_ПРОВЕРОК.md).

Подробности этапов и триггеров — в [основном плане](../akvamilk_mvp_plan.md). Рабочие каналы и сделки компании не менять.

## Проверка ИИ без сборки файлов

Весь файл **07_ПАКЕТ_ДЛЯ_ИИ.md** приложить или скопировать в новый диалог с разрешённым компанией ИИ. Он содержит задание и все входные материалы. Не добавлять файл 04 с эталонами: иначе проверка станет подсказанным ответом. Файл 00 с данными доступа тоже не нужен.

Сопоставить ответ с файлом 04, записать результат в файл 05. Для живой демонстрации достаточно D02; остальные четыре случая — проверка границ подхода.

**Что уже сделано:** материалы и авторские эталонные разборы подготовлены. **Что ещё не подтверждено:** фактическая работа CRM, Telegram, триггеров и независимый прогон ИИ. В журнале они не отмечены выполненными заранее.

Реальные условия компании понадобятся для рабочего пилота. До их получения можно сдать учебный MVP. Если заменить учебные условия, нужно пересчитать эталоны и повторить проверки — не смешивать две базы.
