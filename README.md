# water-milk

Локальное приложение контроля качества ответов менеджеров. Загружает сделки и переписки amoCRM. Кнопка **«Проверить ответ менеджера»** сама запускает ИИ через локальный Codex с входом по подписке ChatGPT, проверяет доказательства и показывает результат. API-ключ модели не используется.

## Запуск приложения

Нужен Python 3.11 или новее. Внешних зависимостей нет.

Дважды нажмите `start.bat` или выполните из папки проекта:

```powershell
python app/server.py
```

Откройте **http://127.0.0.1:8765**. Для остановки нажмите Ctrl+C в консоли. Другой порт: `python app/server.py --port 8766`.

## Как пользоваться

1. Откройте **«Сделки amoCRM»**. Введите адрес аккаунта (по умолчанию `ivanovnn.amocrm.ru`) и действующий токен доступа интеграции. Токен вводите только в приложении, не в переписке с помощником.
2. Нажмите **«Подключить и загрузить сделки»**. После подключения появляются последние изменённые сделки. Поиск выполняется в amoCRM; фильтры ответственного, воронки и состояния применяются к уже загруженным страницам. Для остальных страниц есть **«Загрузить ещё»**.
3. Нажмите **«Открыть чат»** прямо в строке сделки. Окно Chrome откроется автоматически; при первом запуске войдите в amoCRM. Загружать примечания перед чтением чата не нужно.
4. Нажмите **«Посмотреть переписку»**, сверьте сообщения и авторов. Выберите рабочие или учебные правила, а полноту истории подтвердите только после сверки.
5. Нажмите **«Проверить ответы менеджера»**: приложение сохранит переписку, откроет карточку и сразу запустит оценку. Результат появится автоматически. Для отложенной оценки есть **«Сохранить без проверки»**.

Для переписок в примечаниях используйте **«Из примечаний»** у сделки или отметьте до 10 сделок → **«Примечания выбранных»**. Отметьте найденные переписки → **«Добавить выбранные в проверку»** (до 25 за раз), затем откройте диалог и нажмите **«Проверить ответ менеджера»**. Ошибка загрузки примечаний не блокирует прямое открытие чата. Одинаковые данные не создают дубли; изменённый источник сохраняется отдельной версией.

## Подключение проверки по подписке

Нужен Codex CLI с входом через ChatGPT. Если он ещё не установлен:

```powershell
npm install -g @openai/codex
codex.cmd login
```

При входе выберите ChatGPT, а не API-ключ. В Windows используется исполняемый файл Codex, поэтому запрет запуска PowerShell-скриптов не мешает кнопке. В текущей установке вход по ChatGPT уже обнаружен и реальная проверка одной импортированной переписки выполнена.

Приложение использует официальный режим [codex exec](https://learn.chatgpt.com/docs/non-interactive-mode) с JSON Schema и сохранением финального ответа. Запуск ограничен авторизацией `chatgpt`; переменные API-ключей исключены из окружения. Пользовательская конфигурация провайдеров не применяется. Для этой проверки отключены shell, приложения, браузерные инструменты, плагины и хуки, выбран режим только чтения. Переписка и применимые правила передаются в Codex по stdin; модель не должна читать проект. Результат проверяется тем же валидатором цитат и ID, что и ручной импорт. При ошибке структуры допускается одна автоматическая попытка исправления. Используются лимиты доступа Codex вашего аккаунта; при исчерпании лимита или истечении входа приложение показывает причину.

Задание выполняется в фоне, интерфейс показывает этап. Повторный клик во время проверки не создаёт второй запуск. Оценка сохраняется со статусом «Ожидает проверки» для смысловой сверки человеком; средний балл учитывает подтверждённые результаты. Кнопка после завершения позволяет запустить новый разбор. При перезапуске приложения незавершённое задание отмечается прерванным.

Если сейчас загружена только учебная база, рабочий режим использует встроенные общие критерии **GENERAL-QA-1.0**: вежливость, полнота и уместность общения в доступном контексте. Цены, сроки и регламент компании не подменяются учебными: правильность и регламент остаются Н/Д, общего балла нет. Для полной предметной проверки загрузите утверждённые условия компании. Если база компании загружена, но не подходит по дате, её применение блокируется.

Для теста с «Демо-набором» явно выберите **«Учебная: DEMO-1.0»**, даже если при импорте переписка получила метку рабочей. Режим оценки сохраняется в копии базы результата, а исходные сообщения и метка импорта не переписываются. Учебные условия автоматически к рабочим перепискам не применяются.

Текущая рубрика **QA-ANSWER-1.0** оценивает пять характеристик загруженных ответов: правильность, полноту ответа, тон, уместную инициативу и правила общения. Неполная история не блокирует автоматически полноту, инициативу и правила общения, если их можно проверить по видимым сообщениям. Выполнение действий в CRM (например, запись результата в карточку по R07) — вне оценки текста. В результате явно указаны охват `visible_messages` и признак полноты истории. Итог из 100 относится к загруженным ответам, а не к отсутствующим сообщениям или всей работе менеджера. Непроверяемый критерий по-прежнему получает Н/Д; при нём общий балл не рассчитывается. Старые разборы QA-DEMO-1.0 сохраняют исходную более строгую политику.

Ручные кнопки копирования задания и импорта JSON сохранены в свёрнутом блоке **«Ручной перенос через чат (дополнительно)»**.

Учебные D01–D05, загруженные скриптом `mvp/загрузить_сделки.py`, хранятся в обычных примечаниях и распознаются автоматически. Сценарий С01 сопоставляется с ответственным сделки только при явной записи этого соответствия в источнике. Ответственного обычной сделки нельзя автоматически считать автором всех сообщений.

Подключение только читает amoCRM: сделки, пользователей, воронки, примечания и метаданные бесед. Ничего не создаёт и не изменяет в CRM. Кнопка **«Обновить сделки»** запрашивает свежие данные; при открытии приложения с сохранённым подключением список загружается автоматически.

**Ограничение истории чатов:** CRM API сделок/бесед не является выгрузкой всех сообщений чата. Сейчас поддерживаются переписки в примечаниях с явными ролями и учебный формат `- M01, время, автор: «текст»`. Обычная заметка не выдаётся за переписку. Если найдены беседы, приложение сообщает, что для их текстов нужен отдельный доступ канала/провайдера. См. [официальный метод истории чатов](https://www.amocrm.ru/developers/content/chats/chat-api-reference). Универсальный импорт всех мессенджеров по одному CRM-токену не реализован.

## Стандартная интеграция Telegram: чтение через браузер

Добавлен способ получения сообщений в отдельном авторизованном окне amoCRM. Он читает JSON-ответы истории выбранных чатов, которые загружает Chrome, включая фактическую ленту `/ajax/v3/leads/{id}/events_timeline`. Привязанные к контакту события распознаются по составу участников выбранного чата. На реальной сделке проверено получение четырёх сообщений и сохранение переписки; полнота всей истории этим не доказана. Это не публичный стабильный API: при изменении формата потребуется обновление читателя. Код не меняет Telegram webhook, не вызывает `getUpdates`, не отправляет сообщения, не переносит пароли/куки из вашего обычного браузера.

Для этого способа нужен установленный Chrome и дополнительная зависимость:

```powershell
python -m pip install -r requirements-browser.txt
```

1. Перезапустите приложение. Подключите CRM-токен как обычно. Для сопоставления авторов нужен доступ к списку пользователей с `amojo_id`; после обновления подключитесь заново.
2. В разделе «Сделки amoCRM» нажмите **«Открыть чат»** у нужной сделки. Приложение само откроет отдельный Chrome и дождётся готовности окна. Если потребуется, войдите в amoCRM; логин и пароль в приложение не вводятся.
3. Приложение откроет карточку сделки в этом Chrome. Если история не загружается автоматически, откройте беседу Telegram в карточке и прокрутите её назад до нужного начала. Ручного копирования текста нет.
4. В приложении появится число полученных сообщений → **«Посмотреть переписку»**. Проверьте авторов, даты и текст. Если автор или формат неизвестен либо есть неподдерживаемые вложения, импорт блокируется с причиной.
5. Укажите рабочий/учебный режим. Только после сверки отметьте полноту истории, иначе останется «фрагмент». Нажмите **«Проверить ответы менеджера»** — переписка сохранится и оценка запустится автоматически. **«Сохранить без проверки»** позволяет отложить запуск.
6. Результат появится в открывшейся карточке диалога. При ошибке запуска оценки переписка остаётся сохранённой, проверку можно повторить. Данные карточки браузерным способом не проверяются, поэтому регламент остаётся Н/Д.

Нормализованные сообщения выбранных чатов до импорта хранятся в памяти. Профиль этого отдельного Chrome сохраняется в `data/crm-browser-profile` (исключён из Git): вход в аккаунт может сохраняться между запусками. Профиль не включается в JSON/CSV-выгрузки. Закрыть окно чтения или отключить CRM — не то же самое, что выйти из браузерного аккаунта; для выхода используйте меню amoCRM в отдельном Chrome.

В профиле сохранены данные авторизации: папку `data/crm-browser-profile` нельзя публиковать или передавать. При неизвестном формате ответов не используйте «полную историю» как обход ошибки — нужен разбор реального формата. Состояние загрузки показывает число ответов истории, HTTP-статус и этап обработки. Ожидание ответа, пустая выборка, ошибка доступа и ошибка разбора отображаются раздельно. Живое чтение подтверждено на одной сделке; качество оценки нейросетью проверяется отдельно.

По умолчанию токен хранится только в памяти до перезапуска. Опция **«Сохранить подключение на этом компьютере»** использует Windows DPAPI; зашифрованное значение хранится отдельно в локальной БД и не входит в JSON/CSV-выгрузки приложения. Если защита Windows недоступна, подключение остаётся временным с предупреждением, открытый токен на диск не записывается. После переноса БД на другой компьютер/профиль подключитесь заново. Кнопка **«Отключить»** удаляет сохранённый доступ; импортированные диалоги остаются.

## Учебный пример без подключения CRM

1. Нажмите **«Загрузить учебный пример»**: появятся D01–D05 с явно обозначенными авторскими эталонами. Это демонстрация интерфейса, а не прогон нейросети.
2. Откройте диалог, выберите **«Учебная: DEMO-1.0»** → **«Проверить ответ менеджера»**.
3. Приложение само передаст переписку, правила и рубрику Codex по вашей подписке.
4. После проверки цитат и ссылок результат появится автоматически. Учебный эталон останется отдельно в истории.
5. Сверьте замечания по цитатам и ссылкам на правила. Укажите проверяющего, решение и обоснование. Только подтверждённые фактические результаты входят в средний балл.

Для источников без интеграции остаётся раздел **«Добавить вручную»**. Формат — одно сообщение на строку:

```text
Клиент: Сколько стоит доставка?
Менеджер С01: Уточните, пожалуйста, зону доставки.
Клиент: Зона А.
```

Укажите дату, полноту истории и контекст карточки. Время можно сохранить в тексте сообщения.

## Правила компании

Учебная база **DEMO-1.0** неприменима к рабочим перепискам. Пока правил компании нет, доступна только явно обозначенная предварительная проверка по общим критериям. В разделе **«База правил»** загрузите заполненный [шаблон базы компании](examples/company-kb.template.json). Замените заглушки реальными фактами и регламентами, укажите источник, владельца, период действия и новую версию. После проверки владельцем измените статус нужных записей с `draft` на `approved`. Приложение не проверяет полномочия владельца и достоверность указанного источника.

В задание входят только утверждённые правила, действовавшие на дату диалога. В каждом сохранённом разборе остаётся копия использованной базы. При изменении текста базы нужна новая версия. Предложения модели сохраняются как черновики в разборе и сами не изменяют правила.

Привязка к правилам устроена так: **ID сообщения → точная цитата → ID активного правила → объяснение**. Приложение отклоняет неизвестные ID, отсутствующие цитаты, неподходящие баллы и ответы на другой диалог или версию базы. Эта проверка не доказывает правильность смыслового вывода; это задача проверяющего.

При Н/Д хотя бы по одному критерию общего балла нет. Полнота ответа, инициатива и правила общения оцениваются в границах видимых сообщений. Отсутствие данных карточки не препятствует оценке текста, но не подтверждает выполнение действий в CRM. Критический флаг виден независимо от суммы.

## Данные и экспорт

Переписки и журнал решений хранятся в `data/workbench.sqlite3` на этом компьютере; папка исключена из Git. Приложение слушает только `127.0.0.1`, читает данные подключённого аккаунта amoCRM и по нажатию кнопки передаёт выбранный диалог с правилами Codex через вход по ChatGPT. Служебные токены CRM в задание не включаются. Для проверки используйте разрешённые обезличенные переписки.

В обзоре доступен экспорт CSV для Excel; в разделе «Как это работает» — резервная копия JSON. В карточке можно скачать каждый разбор вместе с использованной базой и решениями. Для полного восстановления скопируйте файл SQLite при остановленном приложении; обратная загрузка резервной копии JSON в интерфейсе не реализована.

## Проверка реализации

```powershell
python -m unittest discover -s tests -v
node --check app/static/app.js
node --check app/static/crm.js
node --check app/static/crm-browser.js
node --check app/static/checks.js
```

Node.js нужен только для необязательной проверки синтаксиса JavaScript, для запуска приложения он не требуется. Тесты используют временную БД. Фактический прогон нейросети и настройка CRM не подменяются эталонами или автоматическими тестами.

Для проверки интерфейса в установленном Chrome: `python tests/ui_smoke.py` (нужен Playwright из `requirements-browser.txt`). Проверяются прямое открытие чата без примечаний, ожидание окна, сохранение и запуск оценки, повторные нажатия, выбор учебных правил, ошибки и мобильная вёрстка. Ответы CRM и ИИ синтетические: тест не обращается к аккаунтам и рабочей базе.

Описание устройства и границ: [реализация MVP](mvp/08_ПРИЛОЖЕНИЕ_БЕЗ_API.md). Исходные материалы: [инструкция исполнителю](mvp/00_НАЧАТЬ_ЗДЕСЬ.md) и [план MVP](akvamilk_mvp_plan.md). Разделы прежнего плана о Telegram больше не обязательны для текущего сценария.

## Статус

Реализовано локальное приложение с загрузкой сделок amoCRM, импортом переписок из примечаний и ленты выбранной сделки, дашбордом, версионируемой базой правил, автоматической проверкой через Codex по подписке, решениями проверяющего и экспортом. Живое чтение четырёх сообщений и реальная автоматическая оценка этой переписки проверены. Оценка предварительная: правила компании не загружены, история фрагментарна. Коммерческие условия и пять исходных диалогов в материалах MVP вымышлены. Для предметной эксплуатации нужна утверждённая база компании и калибровка на реальных разрешённых примерах.
